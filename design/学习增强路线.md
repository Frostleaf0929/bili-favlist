# 学习增强路线 · 方向调研 v1

> 日期：2026-11-06 · 状态：待用户拍板方向，未动工
> 背景：界面迁移全部完成（v0.2.0 已发布），下一阶段主攻「数据学习质量」。
> 本文基于三轮联网调研（同类项目 + 弱监督 / 主动学习 / LLM 标注文献）与本机真实数据形态写成。

---

## 0. 结论速览（如果只做三件事）

1. **给复核队列装上"多样性"**（零依赖）：现在的 margin 排序是纯不确定性采样，文献一致证明会重复劳动；改成「不确定性 + 多样性」批量选样，同样 50 条/天覆盖更多长尾。
2. **LLM 标注链升级为"检索增强 + 自报置信 + 分级路由"**（零 Python 依赖，token 不设限）：检索最相似的人工标注当 few-shot，强制 LLM 只能从既有分类中选（Karakeep 的前车之鉴），输出带置信与证据，高置信自动定类、低置信自动进复核。
3. **标签体检（Cleanlab 思想，零依赖）**：用引擎自身预测审计 599 条人工 + 351 条 AI 标注的自洽性——学习的前提是标注可信。

一句话定调：**本项目相对所有同类工具的护城河是"学习闭环 + 盲测考核"**（调研到的 5 个同类工具全是"关键词规则或 LLM 一把梭"，没有一个有评测基准）。所有新方向都必须能用现有盲测 harness 量化验证（64% / 79% / 88% 三个基线数字）。

## 1. 现状基线（2026-11 实测）

| 项 | 值 |
|---|---|
| 语料 | 21,914 条，96 夹，tag 覆盖 97.7% |
| 分类体系 | 8 大组 · 94 叶 · 91 已绑夹 |
| 判定 | 池2个人化 → 规则（手写 6 / 初筛 19 / 强化 207，手工权重）→ 池1热词 → low |

**架构定位**：现在的引擎本质是一套**手工加权的标签函数（Labeling Function）系统**——规则、热词、池2 特征各自投票，权重靠网格搜索 + 共现统计。这恰好是弱监督（weak supervision）研究的标准起点。

## 2. 同类项目与研究扫描

### 2.1 同类工具（B 站收藏夹 / 书签管理）

| 项目 | 做法 | 它没有的（=我们的空间） |
|---|---|---|
| RadiumAg/bilibili-favorites（Chrome 插件） | 关键词规则自动归类 | 无学习、无评测、无保护 |
| madoka-chann/Bilibili-AI-Favorites-Organizer（油猴） | 标题喂 LLM 语义分类后自动移动 | 无复核、无置信路由、无评测、直接改线上数据 |
| jqwgt/bilibili-favlist-classifier（油猴） | 按站内分区归类 | 同上 |
| TLRKFXE/BiliShelf | 本地库突破收藏夹数量限制，重检索 | 定位不同（存储层） |
| Karakeep（自托管书签，标杆项目） | LLM 打标签 + 规则标签引擎双轨；支持 Ollama 本地模型 | 有教训（见下） |

**Karakeep 的两条经验/教训**：
- 其 issue #111 是热门抱怨：LLM 自由发挥发明新标签导致标签体系腐烂 → **必须约束 LLM 从既有分类中选择**（我们要做 LLM 分类时的硬规则）；
- 它同时保留"规则标签引擎"与"AI 打标"双轨 → 印证我们"规则为主、AI 为辅"的架构方向是对的。

### 2.2 方法论文献（每条都映射到一个可落地改动）

| 研究领域 | 核心结论 | 对应本项目 |
|---|---|---|
| **Snorkel / Data Programming**（Ratner 2017, arXiv:1711.10160，1500+ 引用） | 多个弱标注函数投票时，**每个函数的准确率可自动学出**，加权聚合优于手工权重；冲突与相关性被显式建模 | 我们的 207 条强化规则权重全为 1.0、字段权重只有 3 个全局数——都是"手工权重"阶段 |
| **Confident Learning / Cleanlab**（Northcutt 2021, arXiv:1911.00068，1500+ 引用） | 用模型预测的自置信度可系统性找出数据集里的标注错误，有明确数学条件 | 人工 599 + AI 351 条标注从未被审计过；盲测真值（夹名）本身可能有错 |
| **主动学习：不确定性 + 多样性混合采样**（Lilian Weng 综述；Zhu 2008 起 280+ 引用一脉） | 纯不确定性采样会选到冗余样本与离群点；批模式下加多样性/代表性可显著提升同等标注预算的收益 | 复核队列的 margin 排序 = 纯不确定性；「每天 ≤50 条」正是小预算场景 |
| **检索增强分类 / kNN-prompt**（KRA, MDPI 2024 等） | 先检索最相似的已标注样本塞进 prompt 当 few-shot，再做 LLM 分类，显著优于裸 prompt | 我们 599 条人工标注就是现成的"知识库"，从未被 LLM 链路利用 |
| **Human-LLM 协作标注**（WWW 2024，359+ 引用） | LLM 输出带解释，由验证器标记不可靠条目转人工，优于纯 logit 不确定性；LLM 不确定性与准确率强相关（Appen 研究） | AI 批量分类目前无置信路由、无解释、无分级 |
| **轻量本地向量**（ONNX Runtime + MiniLM/BGE） | 无 PyTorch 也能本地跑多语言句向量（onnxruntime + tokenizers，CPU 够用） | 语义层（相似条目 / kNN 信号 / 去重 / 归一化）的全部前提，当前完全缺失 |

## 3. 方向清单（按依赖分档，每项含接入点与验证方式）

### 档位 0 —— 纯统计增强，零新依赖（改 `app_engine.py` 即可）

#### D1 · Snorkel 式信号权重学习（"学习"的正名）

- **思路**：把每个信号源（手写规则、初筛规则、每条强化规则、每个热词键、池2 特征）视为一个标注函数。在已有的可靠标注（人工 599 + 评估集 5843 条夹名真值）上，估计**每个信号源对每个分类的经验准确率/精度**，学出 per-signal-per-category 权重表，替代"207 条强化规则权重全 1.0"和 3 个全局字段权重。冲突消解从"总分相加"升级为"加权投票 + 分歧度输出"。
- **依据**：Snorkel 核心思想（见 §2.2）；本项目 §5.2 网格搜索已证明"权重学出来与直觉相反"（up>tag>title），per-signal 粒度只会更有效。
- **接入点**：`app_engine.py` 的 `score_item()` / `recompute_stats()` / `promote_reinforced_rules()`；新增 `learn_signal_weights()` 与 `settings.signal_weights`。
- **验证**：盲测重跑，对比 64% / 79% 基线；同时输出「权重学习前后 Top20 分歧变化」。
- **风险**：小样本类别上的权重过拟合 → 对 n<10 的分类回退全局权重；权重学习必须只用训练切分（沿用 80/20 纪律）。

#### D2 · 标签体检（Confident Learning 简化版）

- **思路**：对所有已标注（human/ai/human+ai 一致与否）条目，用引擎给全库的预测分布计算"自置信度"——若某条的人工分类在引擎预测里排名很靠后且分差大，flag 出来。输出三类队列：① 人工标注疑似错；② AI 标注疑似错；③ 盲测真值夹本身粒度混乱（如 MV 系列）。**只提示不改写**，进复核队列人工裁决。
- **依据**：Cleanlab 的 self-confidence 思想，简化到无需概率校准即可用（引擎有 score/margin）。
- **接入点**：新增 `/api/labels/audit` 与复核队列新 tab（"标签体检"）。
- **验证**：抽样 30 条 flagged 人工确认错标率；错标修完后盲测是否上升。
- **风险**：引擎预测差≠标注错（也可能是引擎弱）→ 所以只 flag 不改，且按"分差大小"分诊。

#### D3 · 复核队列升级：不确定性 + 多样性混合采样

- **思路**：保留 margin 排序做"不确定性"分，增加"多样性"分：用条目特征（tag 集合 + 标题 bigram 的 Jaccard/TF 相似度，无需嵌入）对候选池贪心批选——每条新入选需与已选集合相似度低于阈值，或直接做「先按相似度聚簇，每簇取 margin 最高者」。目标：每天 50 条覆盖尽量多的不同内容形态。
- **依据**：主动学习文献一致结论（§2.2 第三行）。
- **接入点**：`/api/items?status=review&sort=` 增加策略参数 `smart`；复核页排序 seg 增加"智能批选"。
- **验证**：同样标注 100 条（人工 2 天量），比较"智能批选 vs 纯 margin"两种顺序下的盲测提升幅度。
- **风险**：几乎无；纯前端+排序层改动。

#### D4 · 强化规则质量升级：lift 门槛 + 限额内择优

- **思路**：现在强化规则升级条件是 P≥0.6 且 n≥5，每遍 cap 50 先到先得。改为计算 **lift = P / 该分类的基准占比**（例如"翻唱"在歌曲MV 中占 40% 基线，某词 P=0.98 的 lift 只有 2.45；而在绘画里 P=0.98 可能 lift=10+），按 lift 排序取每遍 top-N；lift<2 的不许升级。
- **依据**：共现强度的标准做法（相对提升而非绝对概率）；直接回应"第 8/9 遍都顶到 cap 50 说明候选溢出"的已知问题。
- **接入点**：`promote_reinforced_rules()`。
- **验证**：强化规则总数应下降但精度上升 → 盲测对比；规则页给每条强化规则显示 lift。
- **风险**：小分类基准占比低会导致 lift 虚高 → 与 n 门槛联合约束。

#### D5 · 评测体系升级（一切优化的度量衡）

- **思路**：① 盲测报告增加 per-leaf precision/recall/F1 表（现在只有重合率一个数）；② 每次 `eval/run` 把报告存档为 `eval_history`，学习页可对比任意两次（防止"调了权重感觉更好"）；③ 增加**时间切分**口径：按 fav_time 取最新 20% 当留出集，回答"对新收藏准不准"（更贴近真实使用）；④ 规则页新增「规则精度榜」——每条规则在评估集上的命中数/正确数，垃圾规则一目了然。
- **接入点**：`run_evaluation()` / 学习页盲测报告 / 规则页。
- **验证**：本身即度量；先跑一次建立 F1 基线存档。
- **风险**：无（纯增量，不动判定逻辑）。

### 档位 1 —— LLM 增强链（不新增 Python 依赖，token 不设限，用现有 OpenAI 兼容配置）

#### D6 · 检索增强标注（kNN-prompt）：让 LLM 站在 599 条人工标注的肩膀上

- **思路**：AI 批量分类时，对每条待分类条目检索最相似的 k=5 条**人工已标注**条目（先用 D3 的 Jaccard 相似度，档位 2 换向量相似），连同其人工分类一起注入 prompt 作 few-shot；同时注入该分类体系的叶分类清单，**硬性要求只能从中选择**（Karakeep issue #111 教训）。
- **依据**：KRA（kNN 检索+LLM 组合在 6 个基准上有效）；RAG-classification 实践。
- **接入点**：`app_server.py` 的 `_run_llm()` / `call_llm()`；prompt 模板进 `settings.llm`。
- **验证**：取评估集 500 条做 A/B——裸 prompt vs 检索增强，比准确率与"拒绝回答率"。
- **风险**：prompt 变长 → token 成本上升（可接受）；相似检索质量差会误导 → 少样例（k=3）起步。

#### D7 · 结构化输出 + 自报置信 + 三级路由（Human-LLM 协作完整版）

- **思路**：LLM 输出强制 JSON：`{category, confidence(0-1), evidence, alternative}`。路由规则：confidence ≥ 阈值A → 直接 AI 定类（status=ai）；A ~ B 之间 → 进复核队列且**附上 LLM 的 evidence 与 alternative**（复核卡新增一行"AI 视角"）；< B 或报"不确定" → 留在 low/长尾。阈值 A/B 用 D9 的校准数据定，不是拍脑袋。
- **依据**：WWW 2024 Human-LLM 协作标注（解释+验证器）；Appen 的"不确定性↔准确率相关"。
- **接入点**：`call_llm()` 输出解析 + `settings.llm.route_thresholds`；复核卡渲染 evidence。
- **验证**：评估集上测"三级路由后 AI 自动部分的精确率 ≥ 目标（如 85%）且人工量下降 X%"。
- **风险**：LLM 自报置信偏乐观 → 必须先做 D9 校准再启用自动档。

#### D8 · 长尾攻坚 + 分类体系生长循环

- **思路**：对 7,721 low + 944 未预测：用 desc + tags + UP 组合喂 LLM（标题无信息量≠无信息量）；同时开启**体系生长**——把 LLM 分类结果中"既有分类都不合适"的条目聚簇（用相似度），LLM 为每簇起名并给出定义，**人工批准**后 `ensure_leaf` 成新叶分类，簇内条目自动成为该新分类的首批弱标注，立即触发热词/强化学习。这是把"94 个叶分类手工攒"变成"体系随数据生长"的机制。
- **依据**：BERTopic 类"聚簇后命名"思路的 LLM 化；Karakeep 反面教训的正向利用（新分类必须人批准）。
- **接入点**：学习页新增「长尾攻坚」卡（进度复用 eval/progress 轮询）；`/api/taxonomy` 已有 ensure_leaf 能力。
- **验证**：长尾消化率（low 存量下降）；新叶分类 30 天后的盲测表现；人工批准成本统计。
- **风险**：LLM 起名质量参差 → 人工批准这道闸不许省；新分类碎片化 → 批准时显示与既有分类的相似簇。

#### D9 · AI 标注置信度校准（让"AI 标注"变成可考核对象）

- **思路**：在评估集（有夹名真值）上跑一批 LLM 分类，得到**每个分类的 LLM 可靠性表**（精确率/召回率/与人工一致率）。产出两个用途：D7 的路由阈值；学习页展示"AI 可靠性榜"——某些分类（如 asmr、cos）LLM 可能 95% 准，某些（MV 系列互串）可能 60%，自动决定哪里能放手。
- **依据**：GovTech 的人机标注一致性框架；AI 标注文献的一致结论（简单任务放手、难任务人工）。
- **接入点**：学习页新增「AI 校准」卡；结果存 `settings.llm.reliability`。
- **验证**：即产出本身。
- **风险**：评估集真值本身粒度混乱（§5.3 分歧榜）→ 校准时同时用组级口径。

### 档位 2 —— 轻依赖嵌入层（需审批安装 `onnxruntime` + `tokenizers`，模型文件 ~100MB）

候选模型：**BAAI/bge-small-zh-v1.5**（中文优化，~100MB，ONNX 可得）或多语言 `paraphrase-multilingual-MiniLM-L12-v2`（B 站标题中日混杂更稳）。嵌入只算一次存本地（2.2 万条 × 384 维，int8 量化后 ~8MB 独立文件），CPU 推理无压力。

#### D10 · 语义向量层（一层数据，五个功能）

- **a. 复核证据卡**：每条待复核条目显示"最相似的 5 条人工已标注"及其分类——人看邻居秒判，标注速度数倍提升；
- **b. kNN 分类信号块**：与规则/热词并列的新信号（k 近邻加权投票），D1 的权重学习一并学它；
- **c. 主动学习多样性**（升级 D3 的 Jaccard 为向量余弦）；
- **d. 语义去重**：跨收藏夹重复收藏检测（写回前避免重复搬运）；
- **e. 标签归一化建议**：`蔚蓝档案` vs `ブルーアーカイブ` vs `碧蓝档案` 语义近邻 → 别名合并建议（tag 基数 28,042 明显有同义碎片）。
- **依据**：ONNX 轻量推理成熟实践（§2.2 末行）；五个功能全部复用同一份向量。
- **接入点**：新增 `src/embedder.py`；向量存 `data/vectors.bin`（不入 app_state.json 防 17.9MB 再膨胀）；新端点 `/api/similar/{aid}`。
- **验证**：抽样 50 对"模型判相似"的人工确认；kNN 信号块单独开关跑盲测对比。
- **风险**：**新依赖装包需按规则审批**（见 §5）；中日混合标题的模型选择需小规模实测。

#### D11 · 写回即部署即评测（回流闭环）

- **思路**：每次真实写回（合法部署）后，被移动条目=引擎的"真实世界预测"；B 站侧的收藏夹结构（人工在网页端的整理）可作为延迟真值回流。同时补上既定 P2 的快照/反向复原——评测闭环的一部分是"敢部署、可回滚"。
- **验证**：写回 50 条后对比如"写回时预测 vs 30 天后人工在 B 站网页端的最终归属"。

### 档位 3 —— 结构性 / 远期

- **D12 增量与漂移**：新导入自动预分类并进"新条目"复核流；盲测按 fav_time 分桶监控漂移（学习效果衰减报警）。
- **D13 协同信号**：UP 维度画像强化（u: 键已在池2 用到，可扩展为"UP × 分类"先验表）；"常一起收藏的夹"共现迁移建议。
- **D14 多属性标签**（谨慎）：单分类之外给条目挂属性标签（语言/完整度/画质），独立于主分类体系——范围大，除非明确需求不建议先做。

## 4. 优先级矩阵与建议节奏

| 波次 | 内容 | 为什么先做 |
|---|---|---|
| **第一波（零依赖，1~2 轮）** | D5 评测升级 → D2 标签体检 → D4 lift 强化 → D3 多样性复核 | 先把度量衡立起来（D5），其他一切改动的收益才可量化；全部零新依赖 |
| **第二波（零依赖 + 现有 LLM 配置）** | D9 AI 校准 → D6 检索增强 → D7 三级路由 → D8 长尾攻坚 | token 不设限的最大杠杆；校准先行防止裸奔自动化 |
| **第三波（需装包审批）** | D10 嵌入层 → D1 Snorkel 式权重学习（向量信号就位后一起学） | 嵌入是多个功能的地基；等前两波把标注质量洗干净再学权重，不被脏标签污染 |
| **持续** | D11 写回回流、D12 增量漂移 | 与既定 P2（快照/复原）合流 |

**总原则**：每个改动合入前跑一次盲测三数字 + F1 对比，退步即回退——这是同类工具都做不到的纪律，也是本项目能把"学习"二字当真的原因。

## 5. 新依赖审批清单（按你的规则，装前必批）

| 包 | 用途 | 体积 | 时机 |
|---|---|---|---|
| `onnxruntime` | 本地 CPU 推理嵌入向量 | ~40MB wheel | 第三波 D10 前 |
| `tokenizers`（HuggingFace） | 分词（BERT tokenizer，含 CJK） | ~3MB | 同上 |
| 模型文件 | BAAI/bge-small-zh-v1.5 或多语言 MiniLM 的 ONNX | 100~470MB | 同上（数据文件，放 data/models/） |
